# Contributing to OpenRower

Thank you for your interest in contributing! Contributions are welcome via issues and pull requests.

## Getting Started

Fork the repository and create a branch from `main`. The project has four parts, and each can be worked on
on its own.

### Android app (`app/`)

- Requirements:
  - a current Android Studio release (the project uses AGP 9.1 and Gradle 9.3);
  - JDK 17 or newer.
- The app targets SDK 36, minSdk 31 (Android 12).
- The package and application ID is `com.smartapes.openrower`, the ID of the Google Play listing. Never
  change it: Play treats a new ID as a different app.
- Command line:
  ```
  ./gradlew assembleDebug        # build
  ./gradlew installDebug         # build and install on a connected phone
  ./gradlew testDebugUnitTest    # unit tests
  ```

### ESP32 firmware (`OpenRowerESP32/`)

The firmware for the OpenRower sensor board. Build it with the Arduino IDE 2 or arduino-cli and the ESP32
core 3.x (tested with 3.1.1 and 3.3.12):

- Board: **ESP32C3 Dev Module**
- USB CDC On Boot: **Enabled**. The sketch refuses to build without it, because the app talks to the
  board over the native USB port.

See [`OpenRowerESP32/README.md`](OpenRowerESP32/README.md) for flashing and the protocol.

### Arduino sketch (`OpenRowerArduino/`)

The original Arduino Nano + BT05/HM-10 build. Open `OpenRowerArduino/OpenRowerArduino.ino` in the Arduino
IDE (1.8+ or 2.x). No external libraries are required.

### Sensor board (`hardware/`)

- Requirements:
  - KiCad 10;
  - Python 3 with KiCad's `pcbnew` module and `numpy`.
- The schematic and board are **generated by the scripts in `hardware/tools/`**. Make changes in the
  scripts, not in KiCad, or they will be lost the next time the files are generated:
  - the netlist is the `PARTS` table in `gen_schematic.py`;
  - placement is `PLACEMENT` in `gen_pcb.py`;
  - routing is done by `route.py`.
- [`hardware/openrower_sensor_circuit.md`](hardware/openrower_sensor_circuit.md) explains the circuit and
  how to regenerate everything (§9).

## Testing without hardware

- **App:** turn on **Test Mode** on the Workout Setup screen. `FakeDataSource` then synthesises a 24 spm
  stroke and a heart rate.
- **Firmware:** set `TEST_MODE 1` in either sketch. The board then streams the same synthetic stroke over its
  real BLE/USB link.
- **Recording real data:** turn on **Debug Logging** in Settings to save every pulse to a CSV file, then:
  ```
  adb pull /sdcard/Android/data/com.smartapes.openrower/files/logs/
  ```
  Attach such a log to bug reports about stroke detection or pace.

## How to Contribute

- **Bug reports** — open an issue with steps to reproduce and expected vs. actual behaviour. Include:
  - the phone and Android version;
  - which hardware you use (sensor board or Arduino) and how it is connected (BLE or USB);
  - the rowing machine model.
- **Feature requests** — open an issue to discuss the idea before starting work.
- **Pull requests** — keep changes focused. Link the related issue in the PR description. Before opening one:
  - run `./gradlew testDebugUnitTest`;
  - compile any sketch you changed;
  - don't commit binaries (APKs, firmware images). Releases are published separately on the
    [releases page](https://github.com/naibaf7/OpenRower/releases).

## Things to keep consistent

### The sensor protocol

The Arduino sketch, the ESP32 firmware and the app all speak the line protocol documented in
[`OpenRowerESP32/README.md`](OpenRowerESP32/README.md#protocol). If you change it:

- update all three sides, plus `FakeDataSource` and `RowingDataParserTest`;
- keep `P` and `H` lines unchanged, so older boards and app versions keep working. Add a new message type
  instead.

### The database

The app's Room database holds people's workout history. If you change an entity:

- bump the version in `WorkoutDatabase`;
- add a `Migration` for it;
- never fall back to a destructive migration.

### Machine profiles

New rowing machines go in `MachineProfiles.BUILT_IN`:

- give each new profile a new negative ID, and never reuse an old one, since saved selections refer to it;
- say in the PR where the constants come from: measurements, the manufacturer, or another project.

### The sensor board

- **Safety:** no sensor mode selection may damage the board, the phone or the rowing machine. The one
  documented exception is 5 V into a 3.3 V-only hall sensor. Concept2 D/E machines carry about 18 V on the
  jack's Ring contact, so Ring must never be clamped into a supply rail. Read §1 and §6 of the circuit notes
  before changing anything around the jack.
- **Checks:** before a PR, make sure DRC and ERC show 0 violations and `tools/check_spacing.py` reports no
  problems.
- **Fabrication files:** regenerate them with `tools/make_fab.py`.

## Code Style

- Kotlin: follow the [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html).
- Arduino / ESP32 (C++):
  - keep interrupt handlers lean, and document any timing assumptions;
  - the ESP32 must never block when no USB host is listening.
- Python (hardware tools): keep the scripts deterministic, so regenerating an unchanged design gives the
  same files.

## Physics Model

If you change the rowing physics (drag factor, stroke detection, pace calculation), please include the
reasoning and any reference papers or real-world measurements in the PR description.
